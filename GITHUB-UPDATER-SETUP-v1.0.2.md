## What was added

1. `electron-updater` dependency.
2. GitHub publish configuration in `package.json`.
3. Electron updater initialization in `electron/main.cjs`.
4. Secure renderer bridge in `electron/preload.cjs`.
5. `Settings → Application Update → CHECK FOR UPDATES` UI.
6. Automatic update check 5 seconds after startup in packaged builds.
7. Background download when a newer GitHub Release is found.
8. Restart & Install prompt after download.
9. Existing NSIS installation is upgraded using the same `appId`.

## First transition

The already-installed v1.0.0/v1.0.1 build does not contain an updater, so the first updater-enabled build must be installed once manually. After that, later releases can be delivered through the updater.

## Build

From the project folder:

```bash
npm install
npm run build:desktop
```

The first `npm install` will install `electron-updater` from `package.json`.

## GitHub Release

For a public GitHub repository, create a GitHub Release such as `v1.0.2`, then upload the Windows installer and the update metadata/artifacts generated by electron-builder. The installed app reads GitHub Releases through `electron-updater`.

For automated publishing with electron-builder, set `GH_TOKEN` in the build environment and use the appropriate electron-builder publish command. Never hard-code a GitHub token into the application source.

## Important repository access note

The GitHub repository used by the updater must be reachable by customer installations. A private GitHub repository requires an authenticated update mechanism; do not embed a personal GitHub token in the app. If the source repository is private, use a separate public releases repository or a properly authenticated update server/CDN for customer updates.
